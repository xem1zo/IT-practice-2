# Практическая работа №2: Интерактивная работа с MySQL в изолированном окружении Docker. Логирование.

## 🎯 Цель работы
Освоить работу с СУБД MySQL внутри Docker-контейнера, научиться настраивать встроенное логирование запросов, создавать представления (VIEW), а также выполнять экспорт (дамп) базы данных для резервного копирования.

## ⚙️ Выполненные шаги

### 1. Настройка окружения и запуск контейнера
* Создан и настроен конфигурационный файл `my.cnf`. В него добавлены параметры для корректной работы с кириллицей (кодировка `utf8mb4`) и включено общее логирование с выводом в таблицу.
* Запущен Docker-контейнер на базе официального образа `mysql:8.0`. Данные сохранены в именованном томе `mysql_data`, а конфигурация проброшена из хоста.

### 2. Настройка логирования и создание структуры БД
* Внутри СУБД активировано логирование (`general_log = 'ON'`, `log_output = 'TABLE'`).
* Создана учебная база данных `sql_practice` с поддержкой `utf8mb4`.
* Создано представление (VIEW) `my_actions`. Оно фильтрует системную таблицу `mysql.general_log`, отсекая служебные запросы (SHOW, SET), и позволяет удобно отслеживать историю действий пользователя.
* Созданы две связанные таблицы: `customers` (клиенты) и `orders` (заказы). Таблицы наполнены тестовыми данными с кириллицей (5 клиентов и 6 заказов).

### 3. Экспорт данных
* Выполнен экспорт лога действий (`my_actions`) в текстовый файл `my_actions_export.txt` для анализа.
* Создан консистентный дамп базы данных `sql_practice` в файл `dump_clean.sql`. При создании дампа использовались флаги `--single-transaction` (для целостности данных) и `--set-gtid-purged=OFF`.

## 📁 Описание файлов в репозитории
* **`my.cnf`** — файл конфигурации MySQL (кодировки и настройки логирования).
* **`dump_clean.sql`** — дамп базы данных `sql_practice`. Может быть использован для полного восстановления БД.
* **`my_actions_export.txt`** — текстовый экспорт лога выполненных действий, полученный через VIEW `my_actions`.
* **`README.md`** — данный файл с описанием проделанной работы.

## 🚀 Как развернуть проект (Восстановление БД)
1. Запустите контейнер.
2. Создайте пустую базу данных.
3. Импортируйте данные из дампа `dump_clean.sql`.
